# Patient-schema synthetic data (v3)

This dataset mirrors the **fields and links** in the user-provided Patient Database Google Sheet inspected on 2026-09-30. It does not contain a copied patient record, phone number, email, WhatsApp ID, free-text prescription, original message, or source spreadsheet export. Every person and record ID begins with `syn_`; names are visibly synthetic labels.

Run `node scripts/patient-schema-synthetic/generate.js` from the repository root. Output is in `output/patient_schema_synthetic_v3_2026-09-30/`; `manifest.json` gives counts and SHA-256 checksums. The JSONL files model eight linked tables: `user`, `patient_adaptation_timeline`, `prescriptions`, `weekly_schedule`, `nudges`, `schedule_state`, `inbound_messages`, and `model_rows`. Source tables with no populated records are intentionally absent.

The database has patient profiles, clinician prescriptions, planned schedule slots, sent nudges, delivery state, and inbound messages. `model_rows.jsonl` joins those synthetic records into the row format required by the frequency experiment. A prescription's `frequency_per_week` describes the clinician's target behaviour and is **not** the model's nudge frequency. The model may only choose one to three prewritten nudge slots per week. Nudge type, pillar, category, tone, action, and message remain fixed in each candidate slot.

The source has very sparse response evidence. Its recorded fields establish a data contract, but they do **not** establish patient response rates or causal effects. Consequently, the synthetic outcomes are generated by the already disclosed, prespecified v2 scenario assumptions. The 7,214 model rows and 1,282 positive outcomes reproduce that v2 generator by design; they are not a new empirical result or evidence of model performance on real patients. Demographic fields without usable source values remain null. All dates, records, and responses are fictional.

The current source-derived structure lacks a reliable `interaction_events` table and has only sparse feedback in `schedule_state` and `inbound_messages`. Before a real-world frequency policy could be evaluated, delivery/response linkage, the 24-hour outcome window, missing delivery timestamps, and patient consent would need to be confirmed prospectively. This dataset supports local integration and protocol testing, not clinical effectiveness claims.
